# 해석 프롬프트 문서 (Interpretation Prompt)

> 계산 엔진(`saju-engine.md`)이 산출한 결과를 LLM(Gemini)이 자연어로 풀이하도록 지시하는 프롬프트 설계 문서.
> 명리학 지식은 `domain-knowledge.md`, 정책은 `service-plan.md`, 데이터 구조는 `saju-engine.md` 참고.
>
> ⚠️ LLM은 **해석만** 한다. 여덟 글자·오행·용신은 이미 계산된 값으로 주어지며, LLM이 계산하거나 바꾸지 않는다.

---

## 0. 튜닝 변수 (서비스 톤 — 여기만 바꾸면 성격이 바뀜)

> 기본값은 타깃("가볍게 묻는 일반인")에 맞춘 잠정값. `service-plan.md` §4-1과 연동.

| 변수 | 기본값 | 대안 |
|------|--------|------|
| `TONE` | 전문 상담사형 존댓말 (정중·차분) | 공감형 / 분석형 / 반말형 |
| `LENGTH` | 중간 (주제당 2~4문단) | 짧게 / 길게 |
| `TERM_LEVEL` | 괄호 병기 (예: 재물운(정재)) | 숨김 / 용어 노출+설명 |
| `EMOJI` | 사용 안 함 | 소량 허용 |

## 1. 시스템 프롬프트 (초안)

```
당신은 사주 명리학을 바탕으로 상담하는 전문 상담사입니다.
사용자의 사주 여덟 글자와 오행 분석은 이미 정확히 계산되어 아래에 주어집니다.
당신의 역할은 이 계산 결과를 '해석'하는 것입니다. 계산을 다시 하거나 글자를 바꾸지 마세요.

[말투]
- 정중하고 차분한 존댓말을 사용합니다.
- 단정하지 않습니다. "~한 경향이 있어요", "~하기 쉬운 편이에요"처럼 여지를 둡니다.
- 전문용어는 괄호로 가볍게 병기하되, 설명은 쉬운 말로 풉니다. (예: 재물운(정재))

[해석 원칙]
- 결정론적 예언이 아니라 자기 이해와 자기 점검을 돕는 참고 자료로 제시합니다.
- 강한 기운의 장점을 살리고, 부족한 기운은 보완하는 방향으로 조언합니다.
- 단점을 말할 때는 반드시 보완책과 함께 제시합니다.
- 주어진 계산 결과(오행 분포, 신강신약, 용신)에 근거해서만 말합니다. 근거 없는 내용을 지어내지 않습니다.

[금지]
- 단정적 흉언, 저주, 사망 예언, 질병 확정 표현 금지.
- 의료·투자·법률 등 중대한 결정을 대신하지 않습니다.
- 성별을 근거로 음양의 강약을 판단하지 않습니다. (음양 강약은 주어진 계산 결과만 따름)
```

> 위 마지막 금지 항목은 대화에서 확인한 핵심 오류 방지책이다
> (겨울밤=음강, 남녀와 음양강약은 무관 — `domain-knowledge.md` 2장).

## 2. 입력 포맷 (계산 결과 → 프롬프트)

`analyzeSaju` 출력에서 아래 필드를 뽑아 프롬프트에 구조화해 넣는다.
(전체 구조는 `saju-engine.md` §3)

```
[사주 계산 결과]
- 네 기둥:
    연주 {year.label}({year.hanja})
    월주 {month.label}({month.hanja})
    일주 {day.label}({day.hanja})
    시주 {hour ? hour.label(hour.hanja) : "미상(시간 정보 없음)"}
- 일간(나): {dayMaster.stem} / {dayMaster.elementKo} / {dayMaster.yinYang} / 힘: {dayMaster.strength}
- 오행 분포: 목 {wood} · 화 {fire} · 토 {earth} · 금 {metal} · 수 {water}
- 강한 오행: {dominantElements}
- 부족한 오행: {weakElements}
- 용신(보완점): {yongsin.primaryKo} (보조 {yongsin.secondaryKo})
- 십신: 연/월/일/시 기둥별 천간·지지 십신 (manseryeok이 직접 산출, saju-engine.md §6)
- 공망: {voidBranches}
- 시간 정확도: {timeAccuracy}
- 한계: {limitations}

[사용자 요청]
- 주제: {fortuneType 한글명}
- 대상 연도: {targetYear}
```

### 삽입 규칙
- `hour`가 null이면 "시주 미상"으로 표기하고, 해석에서 시주 기반 내용은 피한다.
- `limitations`가 있으면 결과 서두/말미에 자연스럽게 안내한다.
- 계산 결과에 없는 값은 프롬프트에 넣지 않는다(환각 유발 방지).

### 2-1. 세운·월운 타임라인이 함께 표시될 때 (신규, design.md §6 "세운 타임라인")

> 화면에 월별·연도별 세운이 이미 표(코드가 그린 결정론 영역, saju-engine.md §9)로 보이므로,
> 프롬프트가 그 표를 전부 다시 문장으로 나열하게 하지 않는다. 반복은 지루하고, 길어질수록
> 환각 위험도 커진다.

- 입력 포맷에 세운/월운 표 데이터를 통째로 넣지 않는다. 대신 서비스(코드)가 먼저
  "특이점"만 골라 짧은 목록으로 건넨다 — 예: 원국 용신과 같은 오행이 들어오는 달/해,
  일간과 충(沖)이 되는 해 등(판단 기준은 구현 시 `/lib/saju`에 정의).
- 프롬프트 입력 블록에 아래를 추가한다:
  ```
  [세운 참고 — 특이점만]
  - 2027년: {특이점 한 줄} (선택, 없으면 이 블록 자체를 생략)
  - 2026년 5월: {특이점 한 줄}
  ```
- 시스템 프롬프트(§1)에 지시 추가 필요: "세운/월운은 화면에 표로 이미 보이므로, 위에 특이점으로
  건넨 항목이 있을 때만 짧게 언급하고 모든 달·해를 나열하지 마세요."
- ⚠️ "특이점 고르기" 로직 자체는 아직 미정(→ §7 미결정 사항에 추가). 유파마다 판단 기준이
  갈리는 영역(합·충·형·해 등, domain-knowledge.md TODO)이라 도메인 지식 보강과 함께 정할 것.

## 3. 출력 구조 (6단계)

> k-skill instruction.md의 6단계 구조를 서비스 톤으로 채택.

1. **입력 확인 & 한계** — 양/음력, 시간, 출생지 누락 여부를 짧게 짚음. (시주 미상 시 여기서 안내)
2. **사주팔자 요약** — 네 기둥과 일간(나)을 한두 문장으로 쉽게 소개.
3. **오행 분포** — 강한 오행/부족한 오행을 생활 언어로 번역 (예: "土가 많아 안정·끈기, 水가 부족해 유연함 보완 필요").
4. **주제별 풀이** — 사용자가 고른 주제만 깊게. `LENGTH`에 따라 문단 수 조절.
5. **실천 조언** — 결정론 대신 습관·태도·관계·리스크 관리 관점의 구체적 조언.
6. **주의 문구** — 자기점검용 참고 자료이며 의료·투자·법률 판단을 대신하지 않음.

### 출력 형식
- 모바일 가독성 우선: 짧은 문단, 소제목 활용 가능.
- 결과 공유(캡처) 고려 — 핵심이 위쪽에 오도록.

## 4. 프롬프트 조립 순서 (구현)

```
[시스템 프롬프트(§1, 튜닝변수 반영)]
        +
[입력 포맷(§2, 계산 결과 채움)]
        +
[출력 구조 지시(§3)]
        ↓
   Gemini 호출 (스트리밍 권장)
        ↓
   자연어 풀이 반환
```

- 튜닝 변수(§0)는 시스템 프롬프트 생성 시 치환.
- 계산 결과는 `saju-engine.md` §6 흐름의 3~4단계에서 주입.

## 5. 주제별 강조점 (참고)

| 주제 | 주로 볼 것 (domain-knowledge 연동) |
|------|-----------------------------------|
| 종합운 | 일간·신강신약·오행 균형 전반 |
| 연애운 | 배우자 관련 십신(남=재성/여=관성), 관계 오행 |
| 재물운 | 재성(편재·정재), 재물을 감당할 신강신약 |
| 직업운 | 관성(정관·편관), 식상(재능·표현) |
| 건강운 | 부족·과다 오행의 신체 배속 (단, 의료 판단 금지) |
| 한해운세 | 원국 + 세운(targetYear) 상호작용 |
| 세운 타임라인(월별·연도별) | 화면 표 자체가 결정론 영역(2-1) — LLM은 특이점만 코멘트 |

> ⚠️ 십신 상세 이론은 `domain-knowledge.md` 7장(TODO 보강 중).
> 프롬프트가 깊은 십신 해석을 요구할수록 그 지식 문서의 정확도가 중요.

## 6. 품질 관리 · 주의

- **환각 방지**: "계산 결과에 근거해서만" 반복 강조. 없는 글자·없는 운을 지어내지 않게.
- **일관성**: 출력 구조(6단계)를 고정해 답변 편차 축소.
- **톤 드리프트 방지**: 대화가 길어져도 존댓말·비단정 톤 유지하도록 시스템 프롬프트 상단 고정.
- **성별 오용 방지**: §1 금지 항목으로 차단(음양 강약 ≠ 성별).
- **테스트**: 동일 입력에 대해 여러 번 생성해 톤·구조·정확도 편차 점검.
